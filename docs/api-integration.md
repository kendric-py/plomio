# Plomio API — руководство по интеграции

Plomio собирает данные с маркетплейсов **Ozon** и **Wildberries**: карточки товаров, отзывы,
поисковую выдачу, товары категорий и продавцов. В этом документе описано всё, что нужно для
интеграции с вашей системой:

- **задачи** — асинхронный сбор данных в больших объёмах: поставили задачу, дождались выполнения,
  забрали результаты;
- **прямые запросы** — синхронное получение одной страницы данных прямо в ответе (до ~20 секунд);
- **баланс и расходы** — проверка баланса кредитов, цены, журнал списаний, лимиты расходов;
- **API-ключи** — доступ без логина и пароля, со сроком жизни и лимитом кредитов на каждый ключ.

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Базовый URL | `https://api.plomio.pro/api` |
| Протокол | HTTPS, REST, JSON в кодировке UTF-8 |
| Авторизация | API-ключ в заголовке `X-API-Key: plm_…` (рекомендуется) или токен `Authorization: Bearer <access_token>` |
| Даты и время | ISO 8601 в UTC, например `2026-10-13T09:15:27.123456Z` |
| Идентификаторы задач | UUID, например `3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12` |
| Маркетплейсы | `ozon`, `wildberries` (строго в нижнем регистре) |

**Слеш в конце пути.** Ручки, у которых в этом документе путь заканчивается на `/`
(например, `POST /api/tasks/`), вызывайте именно так — со слешем. Без него сервер ответит
редиректом `307`, и не все HTTP-клиенты повторяют `POST` после редиректа.

**Регистр значений.** Значения перечислений пишутся ровно как в документе: типы парсинга и статусы
задач — заглавными (`SEARCH_QUERY`, `SUCCEEDED`), маркетплейсы и типы источников списаний —
строчными (`wildberries`, `task`).

## 2. Авторизация

Учётную запись (email и пароль) выдаёт администратор Plomio. Подключить интеграцию можно двумя
способами:

| Способ | Когда подходит |
|---|---|
| **API-ключ** (раздел 2.1) | Рекомендуется для любых интеграций: не нужно хранить пароль и обновлять токен, у ключа свой срок жизни и лимит кредитов, его можно отозвать в один клик |
| **Токен по логину и паролю** (раздел 2.2) | Если ключи использовать нельзя. Токен живёт 60 минут, его нужно периодически получать заново |

### 2.1. API-ключ (рекомендуется)

**Создание.** Ключи выпускаются в личном кабинете Plomio, в разделе **«API-ключи»**: укажите
название (например, по имени системы, которая будет им пользоваться), при желании лимит кредитов и
срок действия. Значение ключа (`plm_…`, 47 символов) показывается **один раз** — сразу сохраните
его в хранилище секретов. Plomio хранит только хэш ключа, поэтому восстановить потерянный ключ
нельзя: отзовите его и выпустите новый.

**Использование.** Передавайте ключ в каждом запросе:

```
X-API-Key: plm_AbCdEfGh...
```

Можно передать его и в `Authorization: Bearer plm_AbCdEfGh...`: сервер отличает ключ от токена по
префиксу `plm_`. Ключ работает, пока его не отозвали и не истёк срок. Обновлять его не нужно.

```bash
curl "https://api.plomio.pro/api/user/me" -H "X-API-Key: $PLOMIO_API_KEY"
```

**Параметры ключа:**

| Параметр | Описание |
|---|---|
| Лимит кредитов | Максимум кредитов, который можно потратить через ключ **за всё время его жизни**. Необязателен |
| Срок действия | Дата, после которой ключ перестаёт работать. Можно выпустить бессрочный ключ |
| Отзыв | Мгновенно и безвозвратно отключает ключ. Статистика трат по нему сохраняется |

Лимит, срок и название можно изменить в кабинете, значение ключа при этом не меняется.

**Что останавливает ключ.** Когда ключ отозван, истёк или исчерпал лимит, траты по нему
прекращаются:

- новые запросы с ключом на создание задач, возобновление задач и прямые запросы получают `402`
  (см. [3](#3-ошибки));
- задачи, созданные через ключ, автоматически встают на паузу (`PAUSED`), как при нулевом балансе;
- отозванным или истёкшим ключом нельзя авторизоваться вообще (`401`). Ключ с исчерпанным
  лимитом по-прежнему читает данные: статусы, результаты, баланс.

Лимит ключа «мягкий», как и остальные лимиты: последнее списание может немного его превысить.
Лимит ключа действует **вместе** с балансом и лимитами учётной записи
([раздел 8.5](#85-лимиты-расходов--get--put-apibillinglimits)): работа блокируется, если
исчерпано хотя бы одно из ограничений.

**Что через ключ недоступно.** Управление ключами (выпуск, изменение, отзыв) — только из личного
кабинета. Запрос с ключом к таким ручкам получит
`403 {"detail": "Not available with an API key"}`: утёкший ключ не сможет выпустить себе новый
ключ или снять собственный лимит.

**Сколько потратил ключ** — видно в кабинете, а из API — через журнал транзакций с фильтром
`api_key_id` (см. [8.3](#83-журнал-транзакций--get-apibillingtransactions)). Идентификатор ключа
указан в кабинете рядом с его названием.

**Рекомендации:**

- отдельный ключ на каждую систему или окружение (прод, тест) — так расходы видны по отдельности, а
  утечка одного ключа не затрагивает остальные;
- задавайте ключу лимит, соответствующий ожидаемому объёму, — это страховка от ошибки в интеграции;
- не храните ключ в коде и репозитории; при подозрении на утечку сразу отзовите его.

| Ситуация | Код | Тело |
|---|---|---|
| Ключ не найден (опечатка, лишние символы) | `401` | `{"detail": "Invalid API key"}` |
| Ключ отозван | `401` | `{"detail": "API key is revoked"}` |
| Срок действия ключа истёк | `401` | `{"detail": "API key is expired"}` |
| Исчерпан лимит кредитов ключа (на тратящих ручках) | `402` | `{"detail": "API key credit limit reached"}` |

### 2.2. Токен по логину и паролю

#### Получение токена — `POST /api/auth/login`

Запрос:

```json
{
  "email": "integration@example.com",
  "password": "your-password"
}
```

Ответ `200 OK`:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

Ошибки: `401` — `{"detail": "Invalid email or password"}`.

#### Использование токена

Передавайте токен в каждом запросе:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Срок жизни токена — 60 минут.** Refresh-токена нет: когда токен истёк, сервер отвечает `401`, и
нужно снова вызвать `POST /api/auth/login`. Рекомендуемая схема: хранить токен в памяти, при любом
`401` один раз получить новый токен и повторить исходный запрос.

| Ситуация | Код | Тело |
|---|---|---|
| Нет ни `X-API-Key`, ни `Authorization` (или он не в формате `Bearer`) | `401` | `{"detail": "Not authenticated"}` |
| Токен невалиден или истёк | `401` | `{"detail": "Invalid or expired token"}` |
| Учётная запись удалена | `401` | `{"detail": "User not found"}` |

### 2.3. Проверка доступа — `GET /api/user/me`

Возвращает текущего пользователя — владельца ключа или токена. Удобно для проверки
работоспособности интеграции.

```json
{
  "id": 42,
  "display_name": "integration@example.com",
  "email": "integration@example.com",
  "role": "client",
  "telegram_id": null,
  "last_active_at": "2026-10-13T09:00:00Z",
  "created_at": "2026-10-01T08:00:00Z"
}
```

## 3. Ошибки

Все ошибки приходят в JSON с полем `detail`. Форма поля бывает двух видов.

**Строка** — бизнес-ошибка:

```json
{ "detail": "Insufficient credits" }
```

**Массив** — тело или параметры запроса не прошли проверку формата (код `422`):

```json
{
  "detail": [
    {
      "type": "greater_than_equal",
      "loc": ["body", "priority"],
      "msg": "Input should be greater than or equal to 1",
      "input": 0
    }
  ]
}
```

`loc` указывает на поле с ошибкой. Обрабатывайте оба варианта: если `detail` — строка, это
сообщение; если массив — список ошибок валидации.

### Сводная таблица кодов

| Код | Значение | Что делать |
|---|---|---|
| `200` / `201` / `204` | Успех | — |
| `401` | Нет ключа/токена, токен истёк, ключ неверный, отозван или истёк | С токеном — получить новый и повторить. С ключом — проверить ключ в кабинете: повтор не поможет |
| `402` | Нет кредитов (`Insufficient credits`), достигнут лимит расходов учётной записи (`Spending limit reached`) или исчерпан лимит API-ключа (`API key credit limit reached`) | Пополнить баланс или поднять соответствующий лимит (см. [2.1](#21-api-ключ-рекомендуется) и [раздел 8](#8-баланс-цены-и-расходы)). **Повторять запрос без этого бессмысленно** |
| `403` | Ручка недоступна с API-ключом (`Not available with an API key`) | Выполнить действие в личном кабинете |
| `404` | Объект не найден (задача, товар, категория, продавец) | Проверить идентификатор или входные данные |
| `409` | Операция недопустима в текущем статусе задачи | Получить актуальный статус задачи |
| `422` | Неверный формат запроса или входных данных | Исправить запрос. Повторять без изменений бессмысленно |
| `503` | Сервис временно не может выполнить запрос | Повторить позже, с паузой |
| `504` | Прямой запрос не уложился во время ожидания | Повторить позже, с паузой |
| `500` | Внутренняя ошибка | Повторить позже; если повторяется — сообщить в поддержку |

## 4. Оплата: как списываются кредиты

У каждой учётной записи есть **баланс кредитов**. Кредиты начисляет администратор Plomio. Через
API пополнить баланс нельзя.

### 4.1. За что списываются кредиты

| Действие | Код действия | Единица | Когда списывается |
|---|---|---|---|
| Создание задачи | `task.create` | 1 задача | Сразу после создания (сейчас обычно бесплатно) |
| Результаты задачи | `result.<ТИП_ПАРСИНГА>`, например `result.SEARCH_QUERY` | 1 собранная сущность (товар, отзыв, карточка) | **Постепенно**, по мере сбора: после каждой сохранённой порции результатов |
| Прямой запрос | `direct.<ТИП>`: `direct.PRODUCT_PAGE`, `direct.REVIEWS`, `direct.SEARCH`, `direct.CATEGORY`, `direct.SELLER` | 1 элемент в ответе | Только за **успешный** ответ |

Актуальные цены за единицу — в `GET /api/billing/pricing` ([раздел 8.2](#82-цены--get-apibillingpricing)).
Цены задаёт администратор, они могут меняться. Не храните их в коде, запрашивайте периодически.

### 4.2. Формула

```
стоимость = ceil(base_cost × multiplier × количество)
```

- `base_cost` — цена единицы действия из прайса;
- `multiplier` — множитель. Для задач он зависит от приоритета (`dimension_code = task_priority`,
  значение — приоритет 1..10). Если правила для значения нет, множитель равен `1`. Для прямых
  запросов множитель не применяется (всегда `1`);
- `ceil` — округление вверх до целого.

Пример: `result.SEARCH_QUERY` стоит 2 кредита, у приоритета 1 множитель `1.5`. Порция из 47
товаров стоит `ceil(2 × 1.5 × 47) = 141` кредит.

### 4.3. Когда работа блокируется

Перед **новой** работой (создание задачи, возобновление задачи, прямой запрос) проверяются
условия:

1. баланс **больше нуля**;
2. не достигнут ни один из ваших лимитов расходов — суточный или месячный (см.
   [раздел 8.5](#85-лимиты-расходов--get--put-apibillinglimits));
3. если работа идёт через API-ключ — ключ действует и его лимит кредитов не исчерпан (см.
   [2.1](#21-api-ключ-рекомендуется)). Задачу, созданную через ключ, нельзя возобновить, пока её
   ключ отозван, истёк или исчерпан, даже из личного кабинета.

Если условие не выполнено, сервер отвечает `402`. Текст ошибки — `Insufficient credits` (нет
кредитов), `Spending limit reached` (достигнут лимит учётной записи), `API key credit limit reached`
(исчерпан лимит ключа) или `API key is revoked or expired` (ключ задачи больше не действует).

Важно:

- **Проверяется только то, что баланс положительный, а не то, что его хватит на всю задачу.**
  Задача с балансом в 1 кредит будет создана.
- **Уже идущая задача не прерывается на середине порции.** Порция результатов списывается целиком,
  поэтому баланс может уйти **в минус**. После этого задача автоматически переходит в статус
  `PAUSED`: следующие страницы не запрашиваются. То же происходит, когда исчерпан лимит ключа, через
  который создана задача. Когда баланс пополнен (или лимит снят),
  возобновите задачу через `POST /api/tasks/{task_id}/resume` (см. [5.7](#57-управление-задачей)).
  Сама задача не возобновится.
- Лимиты расходов «мягкие» по той же причине: последнее списание может немного превысить лимит.

### 4.4. Что не тарифицируется

- Прямой запрос, завершившийся ошибкой (`404`, `422`, `503`, `504`). Платите только за успешные
  ответы.
- Прямой запрос, вернувший 0 элементов (например, последняя пустая страница).
- Получение результатов задачи, выгрузка в xlsx, просмотр статуса, баланса и журнала.

## 5. Задачи

Задача — асинхронный сбор данных по одному или нескольким **входам**: ссылкам, артикулам или
поисковым запросам. Все входы одной задачи относятся к одному маркетплейсу и одному типу парсинга.

Типичный сценарий:

```
POST /api/tasks/                    → получили id задачи
GET  /api/tasks/{id}                → опрашиваем статус, пока он не станет конечным
GET  /api/tasks/{id}/results        → забираем результаты постранично
```

### 5.1. Типы парсинга (`parse_type`) и входы (`inputs`)

| `parse_type` | Что собирает | Один вход — это | Формат результата |
|---|---|---|---|
| `PRODUCT_PAGE` | Полную карточку товара | Ссылка на товар **или** числовой артикул | [`ProductPage`](#72-productpage--карточка-товара), ровно 1 на вход |
| `REVIEWS` | Все отзывы о товаре | Ссылка на товар **или** числовой артикул | [`Review`](#73-review--отзыв), сколько отзывов найдено |
| `SEARCH_QUERY` | Товары поисковой выдачи | Текст запроса **или** ссылка на страницу поиска маркетплейса с фильтрами | [`Product`](#71-product--товар-в-списке) |
| `CATEGORY` | Товары категории | Ссылка на категорию маркетплейса | [`Product`](#71-product--товар-в-списке) |
| `SELLER` | Товары продавца и его профиль | Ссылка на витрину продавца; для Wildberries также числовой id продавца | [`Product`](#71-product--товар-в-списке) + 1 [`SellerProfile`](#74-sellerprofile--профиль-продавца) |

Примеры входов:

| Маркетплейс | Тип | Пример входа |
|---|---|---|
| `wildberries` | `PRODUCT_PAGE` / `REVIEWS` | `https://www.wildberries.ru/catalog/123456789/detail.aspx` или `123456789` |
| `ozon` | `PRODUCT_PAGE` / `REVIEWS` | `https://www.ozon.ru/product/nazvanie-tovara-1234567890/` или `1234567890` |
| `wildberries` | `SEARCH_QUERY` | `кроссовки мужские` или `https://www.wildberries.ru/catalog/0/search.aspx?search=кроссовки&sort=priceup&priceU=100000;500000` |
| `ozon` | `SEARCH_QUERY` | `кроссовки мужские` или `https://www.ozon.ru/search/?text=кроссовки&sorting=price` |
| `wildberries` | `CATEGORY` | `https://www.wildberries.ru/catalog/obuv/muzhskaya/kedy-i-krossovki` |
| `ozon` | `CATEGORY` | `https://www.ozon.ru/category/krossovki-muzhskie-7652/` |
| `wildberries` | `SELLER` | `https://www.wildberries.ru/seller/12345` или `12345` |
| `ozon` | `SELLER` | `https://www.ozon.ru/seller/nazvanie-12345/` |

**Поиск по ссылке с фильтрами.** Настройте на сайте маркетплейса фильтры и сортировку (цена,
бренд, цвет, размер и т. п.) и передайте ссылку со страницы результатов как вход `SEARCH_QUERY`.
Фильтры из ссылки применятся к сбору. Ссылка должна вести на поиск того же маркетплейса, что
указан в `marketplace`: на Wildberries — с параметром `search`, на Ozon — с параметром `text`.
Иначе вход завершится ошибкой.

**Ограничения маркетплейсов.** Маркетплейсы отдают не всю выдачу. Ориентиры: поиск Wildberries —
до ~6000 товаров (60 страниц) на запрос, категория Wildberries — около 26–35 страниц. Чтобы
собрать больше, разбивайте запрос на несколько входов с более узкими фильтрами (например, по
диапазонам цены). Поиск Wildberries может подмешивать товары по упрощённому запросу. Они входят в
результат.

**Отзывы Ozon** собираются при нескольких сортировках с удалением дублей, потому что одна сортировка
Ozon отдаёт не больше ~990 отзывов. Для товаров с тысячами отзывов результат всё равно может быть
неполным.

**Корректность входов на этапе создания не проверяется.** Задача создаётся с любыми строками, а
неверный вход (ссылка на чужой сайт, несуществующий товар) завершится ошибкой уже при выполнении.
Проверяйте входы на своей стороне до отправки.

### 5.2. Создание задачи — `POST /api/tasks/`

Тело запроса:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `parse_type` | string | да | Тип парсинга, см. [5.1](#51-типы-парсинга-parse_type-и-входы-inputs) |
| `marketplace` | string | да | `ozon` или `wildberries` |
| `inputs` | string[] | да | Входы задачи, минимум 1. Порядок сохраняется (`position` 0, 1, 2, …) |
| `ttl_seconds` | integer | да | Сколько секунд задача может ждать в очереди до начала выполнения. Если за это время её не взяли в работу, она получит статус `EXPIRED`. Больше 0. Рекомендуем 3600 и больше |
| `priority` | integer | нет | От 1 (высший) до 10 (низший), по умолчанию `5`. Влияет на очерёдность и на цену (см. [4.2](#42-формула)) |
| `result_limit` | integer \| null | нет | Максимум результатов **на каждый вход** (не на задачу целиком). Не применяется к `PRODUCT_PAGE`. `null` или отсутствие поля — собрать всё доступное. Передавайте положительное число |

Пример:

```bash
curl -X POST "https://api.plomio.pro/api/tasks/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "parse_type": "SEARCH_QUERY",
    "marketplace": "wildberries",
    "inputs": ["кроссовки мужские", "кеды женские"],
    "priority": 5,
    "ttl_seconds": 3600,
    "result_limit": 500
  }'
```

Ответ `201 Created`:

```json
{
  "id": "3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12",
  "parse_type": "SEARCH_QUERY",
  "marketplace": "wildberries",
  "status": "QUEUED",
  "priority": 5,
  "queue_expires_at": "2026-10-13T10:15:27.123456Z",
  "result_limit": 500,
  "error_reason": null,
  "user_id": 42,
  "automation_id": null,
  "pricing_dimension_code": "task_priority",
  "pricing_dimension_value": 5,
  "started_at": null,
  "finished_at": null,
  "created_at": "2026-10-13T09:15:27.123456Z",
  "updated_at": "2026-10-13T09:15:27.123456Z",
  "items": [
    {
      "id": "a1b2c3d4-0000-4000-8000-000000000001",
      "position": 0,
      "input_value": "кроссовки мужские",
      "status": "PENDING"
    },
    {
      "id": "a1b2c3d4-0000-4000-8000-000000000002",
      "position": 1,
      "input_value": "кеды женские",
      "status": "PENDING"
    }
  ]
}
```

**Сохраните `items[].id`.** Каждый результат задачи ссылается на свой вход через `task_item_id`.
По этой связи результаты сопоставляются с входами. Получить список входов позже через
пользовательский API нельзя.

Ошибки:

| Код | `detail` | Причина |
|---|---|---|
| `402` | `Insufficient credits` | Баланс ≤ 0 |
| `402` | `Spending limit reached` | Достигнут суточный или месячный лимит расходов |
| `402` | `API key credit limit reached` | Исчерпан лимит API-ключа, с которым пришёл запрос |
| `422` | массив | Неверный `parse_type`/`marketplace`, пустой `inputs`, `priority` вне 1..10, `ttl_seconds` ≤ 0 |

Задача, созданная через API-ключ, запоминает его: все её списания идут на этот ключ и учитываются
в его лимите.

### 5.3. Статусы задачи

| Статус | Значение | Конечный? |
|---|---|---|
| `QUEUED` | В очереди, ждёт исполнителя | нет |
| `RUNNING` | Выполняется | нет |
| `PAUSED` | Приостановлена: вами или **автоматически из-за нехватки кредитов, лимита расходов или лимита/отзыва API-ключа** | нет — возобновляется только вручную |
| `SUCCEEDED` | Все входы обработаны успешно (или исключены) | да |
| `FAILED` | Обработаны все входы, **хотя бы один** завершился ошибкой. `error_reason = "item_failed"` | да |
| `EXPIRED` | Не была взята в работу до `queue_expires_at` | да |
| `CANCELLED` | Отменена | да |

```
            ┌──────────── pause ───────────┐
            ▼                              │
QUEUED ──► RUNNING ──► SUCCEEDED / FAILED  │
  │  ▲        │                            │
  │  └ resume ┴─► PAUSED ◄─────────────────┘
  │                 (также автоматически при балансе ≤ 0, достигнутом лимите или лимите ключа)
  ├──► EXPIRED   (ttl_seconds истёк, а задача так и не взята в работу)
  └──► CANCELLED (cancel из QUEUED, RUNNING или PAUSED)
```

Важно:

- **`FAILED` не значит «результатов нет».** Если упал один вход из десяти, результаты остальных
  девяти доступны. Всегда забирайте результаты задачи в статусах `SUCCEEDED` и `FAILED`, а также
  `CANCELLED`, если отмена пришлась на выполнение.
- Если исполнитель задачи перезапустился, задача возвращается в `QUEUED` и продолжает с места
  остановки. Уже собранные результаты не теряются и не дублируются.
- Статусы отдельных входов (`PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`, `EXCLUDED`) видны только в
  ответе на создание задачи. Позже они через пользовательский API недоступны. Понять, по какому входу
  нет результатов, можно, сгруппировав результаты по `task_item_id`.

### 5.4. Статус и прогресс — `GET /api/tasks/{task_id}`

Возвращает все поля задачи (как в ответе на создание, но без `items`) и прогресс:

```json
{
  "id": "3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12",
  "parse_type": "SEARCH_QUERY",
  "marketplace": "wildberries",
  "status": "RUNNING",
  "priority": 5,
  "queue_expires_at": "2026-10-13T10:15:27.123456Z",
  "result_limit": 500,
  "error_reason": null,
  "user_id": 42,
  "automation_id": null,
  "pricing_dimension_code": "task_priority",
  "pricing_dimension_value": 5,
  "started_at": "2026-10-13T09:15:31.004211Z",
  "finished_at": null,
  "created_at": "2026-10-13T09:15:27.123456Z",
  "updated_at": "2026-10-13T09:16:02.551870Z",
  "total_items": 2,
  "processed_items": 1,
  "result_count": 612

```

| Поле | Описание |
|---|---|
| `total_items` | Сколько входов в задаче |
| `processed_items` | Сколько входов завершено (успешно, с ошибкой или исключено) |
| `result_count` | Сколько результатов собрано на текущий момент |
| `started_at` | Когда задачу впервые взяли в работу; `null`, если ещё не брали |
| `finished_at` | Когда задача завершилась (`SUCCEEDED`, `FAILED`, `CANCELLED`); у `EXPIRED` — `null` |
| `error_reason` | `item_failed`, если хотя бы один вход упал; иначе `null` |
| `pricing_dimension_code` / `pricing_dimension_value` | Параметр, по которому выбран множитель цены (приоритет задачи) |
| `automation_id` | Для задач, созданных через API, всегда `null` |

Прогресс удобно показывать так: для `PRODUCT_PAGE` — `processed_items / total_items`; для
остальных типов, где объём заранее неизвестен, — `result_count`.

Если задачи нет или она принадлежит другому пользователю — `404 {"detail": "Task not found"}`.

### 5.5. Список задач — `GET /api/tasks/`

Query-параметры:

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `limit` | int 1..500 | 100 | Размер страницы |
| `offset` | int ≥ 0 | 0 | Смещение |
| `status` | string | — | Фильтр по статусу задачи |
| `date_from` | ISO 8601 | — | Создана не раньше (включительно). Без часового пояса считается UTC |
| `date_to` | ISO 8601 | — | Создана не позже (включительно). Без часового пояса считается UTC |

Если `date_from` позже `date_to` — `422`.

Ответ:

```json
{
  "items": [ { "...": "те же поля, что у GET /api/tasks/{task_id}" } ],
  "meta": { "total": 137, "limit": 100, "offset": 0 }
}
```

### 5.6. Результаты задачи — `GET /api/tasks/{task_id}/results`

Результаты можно забирать **в любой момент**, в том числе во время выполнения: они появляются
порциями по мере сбора.

Query-параметры: `limit` (1..500, по умолчанию 100), `offset` (≥ 0, по умолчанию 0).

```json
{
  "items": [
    {
      "id": "5d0f3a3e-9a63-4f7e-b7b1-6c8a1f2e9b10",
      "task_item_id": "a1b2c3d4-0000-4000-8000-000000000001",
      "marketplace": "wildberries",
      "parse_type": "SEARCH_QUERY",
      "payload": {
        "external_id": "123456789",
        "title": "Кроссовки мужские беговые",
        "product_url": "https://www.wildberries.ru/catalog/123456789/detail.aspx",
        "price_text": "3 490 ₽",
        "discount": "-30%",
        "stock": null
      },
      "created_at": "2026-10-13T09:15:40.882193Z"
    }
  ],
  "meta": { "total": 612, "limit": 100, "offset": 0 }
}
```

- Порядок — по времени сохранения (`created_at`), от старых к новым. Новые результаты
  добавляются в конец, поэтому при постраничном чтении идущей задачи можно продолжать с
  `offset`, равного количеству уже прочитанных.
- `id` результата уникален. Результаты одной порции сохраняются с одинаковым временем, и их
  взаимный порядок между запросами не гарантирован. Поэтому при чтении идущей задачи всегда
  дедуплицируйте по `id`. Самый надёжный вариант — дождаться конечного статуса и выгрузить всё
  одним проходом.
- Форма `payload` зависит от `parse_type`, см. [раздел 7](#7-форматы-данных-результаты).
- Если задачи нет или она чужая — `404 {"detail": "Task not found"}`.

**Чтобы выгрузить всё**, повторяйте запрос с `limit=500` и `offset += 500`, пока
`offset < meta.total`.

### 5.7. Выгрузка в Excel — `GET /api/tasks/{task_id}/results/export`

Возвращает **все** результаты задачи файлом `.xlsx`
(`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
`Content-Disposition: attachment; filename="task_<id>_results.xlsx"`). Для каждого типа данных
отдельный лист: товары, карточки, отзывы, продавцы. Формат предназначен для людей. Для
машинной интеграции используйте JSON из [5.6](#56-результаты-задачи--get-apitaskstask_idresults).

### 5.8. Управление задачей

Все ручки ниже возвращают задачу в том же формате, что `GET /api/tasks/{task_id}`.

| Ручка | Из каких статусов | Что делает |
|---|---|---|
| `POST /api/tasks/{task_id}/pause` | `QUEUED`, `RUNNING` | Ставит задачу на паузу |
| `POST /api/tasks/{task_id}/resume` | `PAUSED` | Возвращает задачу в очередь (`QUEUED`) |
| `POST /api/tasks/{task_id}/cancel` | `QUEUED`, `RUNNING`, `PAUSED` | Отменяет задачу (`CANCELLED`) безвозвратно |
| `DELETE /api/tasks/{task_id}` | любой | Удаляет задачу вместе с результатами. Ответ `204` без тела |

**`resume` требует тело** с новым временем ожидания в очереди. Отсчёт идёт от момента
возобновления:

```json
{ "ttl_seconds": 3600 }
```

Перед возобновлением проверяются баланс и лимиты, а для задачи, созданной через API-ключ, — ещё и
сам ключ. Если тратить нельзя — `402`.

**Пауза и отмена во время выполнения срабатывают не мгновенно.** Исполнитель проверяет статус
между страницами данных и может успеть сохранить (и оплатить) ещё несколько порций. Уже собранные
результаты остаются доступны.

Ошибки:

| Код | `detail` | Причина |
|---|---|---|
| `404` | `Task not found` | Задачи нет или она чужая |
| `409` | `Task cannot be paused in its current status` | Пауза не из `QUEUED`/`RUNNING` |
| `409` | `Task is not paused` | Возобновление не из `PAUSED` |
| `409` | `Task cannot be cancelled in its current status` | Отмена уже завершённой задачи |
| `402` | `Insufficient credits` / `Spending limit reached` / `API key credit limit reached` / `API key is revoked or expired` | Только для `resume` |

Повторно запустить задачу в статусе `FAILED` или `EXPIRED` через API нельзя. Создайте новую задачу
(например, только с теми входами, по которым нет результатов).

### 5.9. Хранение результатов

Результаты единоразовых задач хранятся **7 дней**. Забирайте их к себе сразу после завершения
задачи.

### 5.10. Пример: полный цикл на Python

С API-ключом клиент сводится к одному заголовку — логин и обновление токена не нужны:

```python
import os
import time
import requests

BASE = "https://api.plomio.pro/api"
TERMINAL = {"SUCCEEDED", "FAILED", "EXPIRED", "CANCELLED"}


class PlomioClient:
    def __init__(self, api_key: str):
        self.session = requests.Session()
        self.session.headers["X-API-Key"] = api_key

    def request(self, method: str, path: str, **kwargs) -> requests.Response:
        kwargs.setdefault("timeout", 60)
        response = self.session.request(method, f"{BASE}{path}", **kwargs)
        if response.status_code == 401:
            # Ключ отозван, истёк или неверен — повтор не поможет, нужен новый ключ.
            raise RuntimeError(f"API-ключ не принят: {response.json()['detail']}")
        return response


client = PlomioClient(os.environ["PLOMIO_API_KEY"])

# 1. Создаём задачу
response = client.request("POST", "/tasks/", json={
    "parse_type": "SEARCH_QUERY",
    "marketplace": "wildberries",
    "inputs": ["кроссовки мужские"],
    "ttl_seconds": 3600,
    "result_limit": 1000,
})
if response.status_code == 402:
    raise RuntimeError(f"Нет кредитов или исчерпан лимит: {response.json()['detail']}")
response.raise_for_status()
task = response.json()
task_id = task["id"]
inputs_by_item_id = {item["id"]: item["input_value"] for item in task["items"]}

# 2. Ждём завершения
while True:
    task = client.request("GET", f"/tasks/{task_id}").json()
    if task["status"] in TERMINAL:
        break
    if task["status"] == "PAUSED":
        # Пауза могла быть автоматической: нет кредитов, лимит учётной записи или лимит ключа
        balance = client.request("GET", "/billing/balance").json()["balance"]
        print(f"Задача на паузе, баланс: {balance}")
        break
    time.sleep(10)

# 3. Забираем результаты постранично
results, offset = [], 0
while True:
    page = client.request(
        "GET", f"/tasks/{task_id}/results", params={"limit": 500, "offset": offset},
    ).json()
    results.extend(page["items"])
    offset += len(page["items"])
    if not page["items"] or offset >= page["meta"]["total"]:
        break

print(task["status"], len(results), "результатов")
```

С токеном вместо ключа клиент такой же, но заголовок `Authorization: Bearer <token>` выставляется
после `POST /api/auth/login`, а при `401` нужно один раз заново получить токен и повторить запрос.

## 6. Прямые запросы

Прямой запрос синхронно возвращает **одну страницу** данных прямо в HTTP-ответе. Подходит, когда
данные нужны сейчас: карточка товара по артикулу, первая страница выдачи, свежие отзывы.

Общие правила:

- Все ручки — `GET`, путь начинается с `/api/marketplace/{marketplace}`, где `{marketplace}` —
  `ozon` или `wildberries`.
- **Время ответа — до ~20 секунд.** Ставьте таймаут HTTP-клиента не меньше 30 секунд. Если
  сервис не уложился, придёт `504`.
- Баланс, лимиты и лимит API-ключа проверяются **до** запроса к маркетплейсу. Если тратить
  нельзя — `402`, и обращения к маркетплейсу не будет.
- Списание идёт только за успешный ответ: по 1 единице на каждый возвращённый элемент
  (карточка — 1 единица). Ошибки и пустые страницы бесплатны.
- В каждом успешном ответе есть `request_id`. Укажите его, если обращаетесь в поддержку по
  конкретному запросу. По нему же списание видно в журнале расходов (`reference_type = direct`,
  `reference_id = request_id`).

### 6.4. Категория — `GET /api/marketplace/{marketplace}/category`

| Параметр | Описание |
|---|---|
| `url` | Ссылка на категорию маркетплейса, 1–500 символов |
| `page_key` | Необязательный ключ следующей страницы |

Ответ — `request_id`, `next_page_key`, `items: Product[]`. Стоимость — по 1 единице
`direct.CATEGORY` за товар.

### 6.5. Товары продавца — `GET /api/marketplace/{marketplace}/seller`

| Параметр | Описание |
|---|---|
| `seller` | Ссылка на витрину продавца или числовой id продавца (id — только для Wildberries), 1–500 символов |
| `page_key` | Необязательный ключ следующей страницы |

Ответ — `request_id`, `next_page_key`, `items: Product[]`. Профиль продавца прямой запрос не
возвращает: он есть только в задачах `SELLER`. Стоимость — по 1 единице `direct.SELLER` за товар.

### 6.6. Постраничный обход (`page_key`)

1. Первый запрос — без `page_key`.
2. В ответе есть `next_page_key`. Если он не `null`, передайте его в следующий запрос как
   `page_key`, **не меняя остальных параметров** (тот же маркетплейс и тот же
   `article`/`query`/`url`/`seller`).
3. `next_page_key = null` — страниц больше нет. Последняя страница может быть пустой.

Свойства ключа:

- **Ключ живёт 15 минут.** Просроченный ключ даёт `422 {"detail": "Invalid or expired page key"}`.
  Начните обход заново, без `page_key`.
- Ключ привязан к маркетплейсу и входу. С другим `query` или `url` он тоже даёт `422`.
- Ключ — непрозрачная строка. Не разбирайте и не изменяйте её.

Для сбора большого объёма (сотни страниц) удобнее и надёжнее **задачи**: они сами проходят все
страницы, переживают сбои и не требуют держать соединение.

### 6.7. Ошибки прямых запросов

Сервис намеренно не передаёт технические подробности сбоев маркетплейсов. Ответы сведены к
фиксированному набору:

| Код | `detail` | Когда | Списание |
|---|---|---|---|
| `402` | `Insufficient credits` / `Spending limit reached` / `API key credit limit reached` | Баланс ≤ 0, достигнут лимит учётной записи или лимит ключа | нет |
| `404` | `Product not found` | Товара нет (карточка, отзывы) | нет |
| `404` | `Category not found` | Категории нет | нет |
| `404` | `Seller not found` | Продавца нет | нет |
| `422` | `Invalid article` | Неверный артикул | нет |
| `422` | `Invalid search query` | Пустой или неверный поисковый запрос либо ссылка | нет |
| `422` | `Invalid category url` | Неверная ссылка на категорию | нет |
| `422` | `Invalid seller` | Неверный продавец | нет |
| `422` | `Invalid or expired page key` | Ключ страницы истёк или не подходит к запросу | нет |
| `422` | массив | Не передан обязательный параметр, превышена длина, неверный `marketplace` | нет |
| `503` | `Service temporarily unavailable, please try again later` | Временный сбой | нет |
| `504` | `Request timed out, please try again later` | Не уложились во время ожидания | нет |

`503` и `504` безопасно повторять: при ошибке кредиты не списываются. Делайте паузу между попытками
(например, 2, 5, 10 секунд) и ограничьте их число (3–5).

## 8. Баланс, цены и расходы

Все ручки — для текущего пользователя (владельца ключа или токена). Баланс и журнал общие на всю
учётную запись: запрос с API-ключом видит все траты, а не только траты этого ключа (их можно
отфильтровать по `api_key_id`).

### 8.1. Баланс — `GET /api/billing/balance`

```json
{ "balance": 15230 }
```

`balance` — целое число кредитов. **Может быть отрицательным**, если идущая задача списала больше,
чем оставалось (см. [4.3](#43-когда-работа-блокируется)). Пока баланс ≤ 0, новая работа
блокируется (`402`).

### 8.2. Цены — `GET /api/billing/pricing`

Прайс, по которому можно заранее оценить стоимость.

```json
{
  "actions": [
    {
      "id": 3,
      "action_code": "result.SEARCH_QUERY",
      "description": "Результат поиска",
      "base_cost": 2,
      "unit_label": "товар"
    },
    {
      "id": 8,
      "action_code": "direct.PRODUCT_PAGE",
      "description": "Прямой запрос карточки",
      "base_cost": 5,
      "unit_label": "карточка"
    }
  ],
  "rules": [
    {
      "id": 1,
      "dimension_code": "task_priority",
      "value_min": 1,
      "value_max": 1,
      "multiplier": "1.50"
    }
  ]
}
```

Значения в примере условные. Как пользоваться прайсом:

- `base_cost` — цена единицы в кредитах; `0` — действие бесплатно;
- `rules` с `dimension_code = "task_priority"` — множитель для задач с приоритетом в диапазоне
  `value_min..value_max` (включительно). Нет подходящего правила — множитель `1`;
- `multiplier` приходит **строкой** (десятичное число). Преобразуйте его в decimal, не во float;
- правила с `dimension_code = "automation_check_frequency"` относятся к автоматизациям и для задач
  не важны.

Оценка стоимости задачи: `ceil(base_cost(result.<parse_type>) × multiplier(priority) × ожидаемое
число результатов)`. Ожидаемое число результатов можно ограничить через `result_limit` × число
входов (кроме `PRODUCT_PAGE`, где результат один на вход). Фактическая стоимость может немного
отличаться: округление вверх применяется к каждой порции отдельно.

### 8.3. Журнал транзакций — `GET /api/billing/transactions`

Все списания и начисления, новые сверху.

Query-параметры:

| Параметр | Описание |
|---|---|
| `limit` | 1..500, по умолчанию 100 |
| `offset` | ≥ 0, по умолчанию 0 |
| `reference_type` | `task`, `automation` или `direct` |
| `reference_id` | Идентификатор источника: id задачи или `request_id` прямого запроса |
| `kind` | `spend` — только списания, `grant` — только начисления |
| `api_key_id` | Только траты через этот API-ключ (идентификатор ключа из кабинета) |
| `date_from` / `date_to` | Период (ISO 8601, UTC, включительно) |

```json
{
  "items": [
    {
      "id": 90211,
      "amount": -141,
      "balance_after": 15230,
      "action_code": "result.SEARCH_QUERY",
      "reference_type": "task",
      "reference_id": "3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12",
      "transaction_metadata": {
        "quantity": 47,
        "unit_cost": "2",
        "multiplier": "1.50",
        "dimension_code": "task_priority",
        "dimension_value": 1
      },
      "api_key_id": 3,
      "created_at": "2026-10-13T09:15:40.901455Z"
    },
    {
      "id": 90001,
      "amount": 20000,
      "balance_after": 20000,
      "action_code": null,
      "reference_type": null,
      "reference_id": null,
      "transaction_metadata": { "comment": "Пополнение по счёту №123" },
      "api_key_id": null,
      "created_at": "2026-10-10T12:00:00Z"
    }
  ],
  "meta": { "total": 2, "limit": 100, "offset": 0 }
}
```

- `amount < 0` — списание, `amount > 0` — начисление.
- `balance_after` — баланс сразу после этой транзакции.
- `transaction_metadata` — расшифровка расчёта для списаний или комментарий администратора для
  начислений. Точный набор ключей может отличаться. Опирайтесь на `amount`, а не на расшифровку.
- `api_key_id` — ключ, через который создана оплаченная работа; `null` — работа создана по токену
  (или это начисление). Списания задачи, созданной через ключ, все несут этот ключ.
- Одна задача порождает **много** списаний: по одному на каждую порцию результатов.

**Сколько потратил ключ за период:** `GET /api/billing/transactions/by-reference?api_key_id=3&date_from=…`
вернёт траты ключа по задачам и прямым запросам; сумма `total_amount` по всем строкам — расход
ключа. Общий расход ключа за всё время и остаток лимита видны в кабинете.

### 8.4. Расходы

**Сколько стоила конкретная задача или прямой запрос** —
`GET /api/billing/spending/{reference_type}/{reference_id}`:

```
GET /api/billing/spending/task/3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12
GET /api/billing/spending/direct/9c1e4b7a2f5d4e8b9a0c3d6f1e2b4a7c
```

```json
{ "total_spent": 1830, "transactions_count": 14 }
```

Для чужого или несуществующего идентификатора возвращаются нули, а не `404`.

**Расходы, сгруппированные по источникам** — `GET /api/billing/transactions/by-reference`.
Принимает те же фильтры (включая `api_key_id`) и пагинацию, что журнал. Начисления без источника в
группировку не входят.

```json
{
  "items": [
    {
      "reference_type": "task",
      "reference_id": "3f6c1f0e-8a4b-4c3e-9d2a-1b7e5c9f0a12",
      "total_amount": -1830,
      "transactions_count": 14,
      "first_at": "2026-10-13T09:15:40Z",
      "last_at": "2026-10-13T09:21:12Z"
    }
  ],
  "meta": { "total": 1, "limit": 100, "offset": 0 }
}
```

**Итоги за период** — `GET /api/billing/stats?date_from=…&date_to=…`. Без периода — за всё время.
Все суммы положительные, в кредитах:

```json
{
  "total_spent": 50210,
  "tasks_spent": 41000,
  "automations_spent": 1210,
  "direct_spent": 8000,
  "date_from": "2026-10-01T00:00:00Z",
  "date_to": "2026-10-13T23:59:59Z"
}
```

**По дням (UTC)** — `GET /api/billing/stats/daily?date_from=…&date_to=…`. Те же поля для каждого
дня плюс `day` (`YYYY-MM-DD`). Дни без списаний не возвращаются.

**Выгрузка журнала в CSV** — `GET /api/billing/transactions/export`. Те же фильтры, что у журнала,
но без пагинации. Файл в UTF-8 с BOM, открывается в Excel; в последней колонке — идентификатор
API-ключа.

### 8.5. Лимиты расходов — `GET` / `PUT /api/billing/limits`

Вы можете сами ограничить расходы учётной записи: например, чтобы ошибка в вашей интеграции не
потратила весь баланс.

`GET /api/billing/limits`:

```json
{
  "daily_limit": 10000,
  "monthly_limit": 200000,
  "spent_today": 3120,
  "spent_this_month": 48770,
  "is_limit_reached": false
}
```

`PUT /api/billing/limits` **заменяет оба лимита целиком**. `null` или отсутствие поля снимает
лимит:

```json
{ "daily_limit": 10000, "monthly_limit": 200000 }
```

- Лимиты — целые числа ≥ 1. `daily_limit` не может быть больше `monthly_limit`, иначе `422`.
- Сутки и месяц считаются по UTC: сутки — с 00:00 UTC, месяц — календарный.
- Когда лимит достигнут, новые задачи, возобновления и прямые запросы получают
  `402 Spending limit reached`, а идущие задачи встают на паузу. Если нужно продолжить работу
  сегодня, поднимите или снимите лимит.
- Это лимиты **всей учётной записи** — они действуют на все ключи и токены сразу. Чтобы ограничить
  отдельную интеграцию, задайте лимит её API-ключу (см. [2.1](#21-api-ключ-рекомендуется)).

## 9. Задачи или прямые запросы: что выбрать

| | Задачи | Прямые запросы |
|---|---|---|
| Режим | Асинхронно: создали, опрашиваете статус | Синхронно: данные в ответе |
| Время | От секунд до часов, зависит от объёма и очереди | До ~20 секунд на страницу |
| Объём | Тысячи входов и все страницы автоматически | Одна страница за запрос |
| Устойчивость к сбоям | Сервис сам повторяет и продолжает с места остановки | При `503`/`504` повторяете вы |
| Отзывы Ozon | Обход нескольких сортировок, больше уникальных отзывов | Постранично в одной сортировке |
| Профиль продавца | Есть | Нет |
| Когда использовать | Регулярные выгрузки, большие объёмы, массовая обработка | Интерактивные сценарии, точечная проверка товара, «первая страница прямо сейчас» |

## 10. Рекомендации по надёжной интеграции

1. **Авторизация.** Используйте API-ключ: отдельный на каждую систему, с лимитом кредитов, в
   хранилище секретов. При утечке — сразу отзовите. Если работаете по токену — получайте новый
   при `401` и повторяйте запрос, не логиньтесь перед каждым запросом.
2. **Опрос статуса.** Опрашивайте `GET /api/tasks/{id}` раз в 5–15 секунд, для больших задач — реже.
   Для пачки задач используйте `GET /api/tasks/?status=RUNNING`, а не отдельный запрос на каждую.
3. **Не ждите бесконечно.** Конечные статусы — `SUCCEEDED`, `FAILED`, `EXPIRED`, `CANCELLED`.
   `PAUSED` сам не меняется: обработайте его отдельно (проверьте баланс и лимиты, затем
   `resume`).
4. **Забирайте частичные результаты.** У `FAILED` и `CANCELLED` тоже могут быть данные.
5. **Сопоставление входов.** Сохраняйте `items[].id` из ответа на создание и группируйте
   результаты по `task_item_id`.
6. **Дедупликация.** Для результатов используйте `id`, для отзывов — `external_uuid`, для товаров —
   `external_id`.
7. **Повторы.** `503`, `504` и `500` повторяйте с паузой и ограниченным числом попыток. `402`, `404`
   и `422` не повторяйте без изменения условий.
8. **Повторное создание задач.** Если ответ на `POST /api/tasks/` не дошёл (таймаут сети), задача
   могла создаться. Прежде чем создавать её снова, проверьте `GET /api/tasks/` с `date_from` на
   момент отправки.
9. **Контроль расходов.** Перед большой выгрузкой проверьте `GET /api/billing/balance`, оцените
   стоимость по `GET /api/billing/pricing`, ограничьте объём через `result_limit` и задайте лимиты
   расходов — учётной записи и API-ключа.
10. **Таймауты HTTP-клиента:** обычные ручки — 30–60 секунд, прямые запросы — не меньше 30 секунд,
    выгрузка xlsx/CSV больших задач — 120 секунд и больше.
11. **Срок хранения.** Результаты задач хранятся 7 дней. Сохраняйте их у себя.

| `POST` | `/api/tasks/` | Создать задачу |
| `GET` | `/api/tasks/` | Список задач |
| `GET` | `/api/tasks/{task_id}` | Статус и прогресс |
| `GET` | `/api/tasks/{task_id}/results` | Результаты (JSON, постранично) |
| `GET` | `/api/tasks/{task_id}/results/export` | Все результаты в xlsx |
| `POST` | `/api/tasks/{task_id}/pause` | Пауза |
| `POST` | `/api/tasks/{task_id}/resume` | Возобновить (тело `{"ttl_seconds": N}`) |
| `POST` | `/api/tasks/{task_id}/cancel` | Отменить |
| `DELETE` | `/api/tasks/{task_id}` | Удалить с результатами |

### Прямые запросы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/marketplace/{marketplace}/product/{article}` | Карточка товара |
| `GET` | `/api/marketplace/{marketplace}/product/{article}/reviews` | Отзывы (`page_key`) |
| `GET` | `/api/marketplace/{marketplace}/search?query=` | Поиск (`page_key`) |
| `GET` | `/api/marketplace/{marketplace}/category?url=` | Товары категории (`page_key`) |
| `GET` | `/api/marketplace/{marketplace}/seller?seller=` | Товары продавца (`page_key`) |
