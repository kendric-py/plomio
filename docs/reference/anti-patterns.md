# Антипаттерны

Список того, что в этом проекте делать нельзя. Если код нарушает один из пунктов — его нужно переписать
перед мержем.

## Функции

- **Не писать функции внутри функций.** Вложенные (nested) функции запрещены — выносить их на верхний
  уровень модуля.
- **Не делать импорты внутри функций.** Все импорты — на уровне модуля, в начале файла.
- **Не создавать циклические импорты.** Если возникает циклическая зависимость между модулями — это
  повод пересмотреть границы модулей/слоёв, а не обходить проблему локальным импортом.

## Именование

- **Не использовать сокращённые имена переменных** (`mp` вместо `marketplace`, `tm` вместо
  `transaction_manager` и т.д.) — всегда писать название полностью.

## Вызовы функций

- **Всегда указывать именованные аргументы** при вызове функций (keyword arguments), не полагаться на
  позиционную передачу.

## Структура пакетов

- **Не создавать файлы `__init__.py`.**

## Типизация

- **Не импортировать типовые конструкции не из того модуля.** Например, `Tuple` берётся из `typing`
  (или используется встроенный `tuple[...]`), а не `from ast import Tuple` — это другой класс
  (AST-нода `ast.Tuple`), который случайно совпадает по имени, но не работает как generic-тип.
- **Аннотация возвращаемого типа обязана соответствовать тому, что функция реально возвращает.**
  Не аннотировать вызовом типа как функции (`Tuple(A, B)` вместо `Tuple[A, B]`) и не указывать тип,
  не совпадающий с фактическим значением (например, `AsyncSession`, когда на деле возвращается фабрика
  `sessionmaker`).

  Пример бага, который это правило должно было предотвратить: `core/database.py` содержал
  `from ast import Tuple` и `-> Tuple(AsyncEngine, AsyncSession)` вместо `from typing import Tuple`
  и `-> Tuple[AsyncEngine, sessionmaker]`.
