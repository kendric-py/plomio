# js_runtime/debug/wb — отладка и проверки Wildberries

Рабочий код — в `../../ready/wb/`. Python-скрипты сами добавляют его в `sys.path`.

## Проверки (тесты)
| Файл | Что делает | Запуск |
|---|---|---|
| `wb_validate.py` | Генерирует N сессий через `wb_flow_warm` и валидирует каждую **валидатором приложения** (`apps.worker_sessions.src.generation.validation.validate_session`); печатает долю валидных и тайминги. Корень репо добавляет в `sys.path` сам | `python debug/wb/wb_validate.py [N=10] [lean]` |
| `wb_check.py` | Прогон `wb_flow` (холодный Node): получает токен и проверяет его реальным запросом к поисковому API WB (`P`, `API`, `H` — параметры запроса, их импортирует `wb_reuse.py`). Печатает итог | `python debug/wb/wb_check.py` |
| `wb_reuse.py` | Берёт один токен (`wb_flow_warm`, lean) и делает 12 поисковых запросов с ним подряд, затем один запрос с другим User-Agent — проверка, переживает ли токен повторное использование и привязан ли к UA | `python debug/wb/wb_reuse.py` |

## Отладка и адаптация
| Файл | Что делает | Когда нужен |
|---|---|---|
| `trace.js` | Запускает challenge-скрипт в `vm` с логирующим Proxy над jsdom-окном: какие глобалы читает скрипт; печатает `OK`/цепочку причин ошибки. `node trace.js <script.js> <payload.txt>` | Решатель падает (`E2xx`) — найти недостающее окружение для `ready/wb/env_min.js` |
| `run_script.js` | Выполняет скрипт в jsdom и показывает, какие глобалы он добавил. По умолчанию берёт `ready/wb/cache_438ddd46c1de1715.js`; путь можно передать аргументом | Посмотреть, что регистрирует новая сборка |

При смене сборки WB новый скрипт сам попадёт в `ready/wb/cache_<hash>.js` при первом прогоне потока.
